## 素材情况

## 卡面接入

### 转换管线

`cut_square/*.png`（单张 ~950KB）→ **512px WebP q85**（单张 ~26KB，101 张共 2.3MB）→ `app/src/main/assets/cards/NNN.webp`。

- 选 WebP：minSdk 24 > 18，透明通道有保障；PNG 直塞要 90MB+，WebP 后 APK 仅 8.4MB
- 选 512px：展示条卡 104dp，xxxhdpi 4x 也就 416px，512px 留有余量
- minSdk 24 起 WebP 无兼容问题（有损+透明需 API 18）

### 代码改动

- `CardCatalog.kt`：TOTAL 100 → 101；新增中文名 / 英文种名 / 分类字段与 `displayName()`；稀有度底子调整为 001-060 普 / 061-085 铜 / 086-095 银 / 096-100 金 / 101 钻（大黄蜂压轴）
- `ui/view/CardArt.kt`（新增）：assets → LruCache（1/8 堆内存，4-48MB 夹紧）+ 单线程串行解码 + 主线程回调；回调带 id 比对，防 RecyclerView 复用串卡
- `CardView.kt`：`drawFace` 由编号数字改为 萌宠图（86% 宽，顶部 5%）+ 顶部 No.xxx + 底部名称 + 稀有度胶囊；**未收集态用 ColorMatrixColorFilter 把图染成 #2A3350 暗剪影**（亮度清零、保留 alpha，轮廓可见但有悬念）；生成中剪影（SILHOUETTE 模式）保持通用黑卡 + ?，不剧透是哪张
- 文案同步：图鉴详情 / 专注完成 / 成就 / 兑换 / 关于，"编号 N" → "No.N 名称"，100 → 101

### 经验

- Kotlin 里 `Paint.setFilterBitmap()` 的属性语法是 **`isFilterBitmap`**，写 `filterBitmap` 编译不过（这次踩了）
- `LruCache<Int, Bitmap>` 重写 `sizeOf` 返回 KB，构造参数传 KB；被逐出的位图若仍被 View 持有引用，GC 不会收，安全
- 未收集剪影用 ColorMatrix 把 RGB 全部清零 + 固定偏移（42,51,80）、alpha 行保持 `0 0 0 1 0`，比 `brightness(0)` 纯黑在深底上更有层次

## 图标接入（focus_B 涟漪）

- **自适应图标**（Android 8+）：108dp 画布，可见区中心 72dp、安全区 66dp
  - 前景：不透明深蓝对角渐变（#1A1C42 → #0D0D22）+ 涟漪整体缩放 k=0.72（最外环 0.444N·k ≈ 0.32N < 安全区半径 0.333N）
  - 用 design_v2.py 的 `icon_ripple()` 改造：去掉底色、画在透明层、光晕改为向透明渐隐，再 alpha_composite 到渐变底上
  - 前景直接做**不透明**（渐变烤进去），背景层只兜底纯色 `#0D0D22`，省去 XML gradient 角度换算的坑
- **旧版图标**（< Android 8）：`focus_B_ripple_1024.png` 直接 LANCZOS 缩放到 48/72/96/144/192
- `ic_launcher.xml` 前景引用从 `@drawable`（旧矢量）改为 `@mipmap/ic_launcher_foreground`（各密度 PNG）
- 重生成脚本：`/data/user/work/make_launcher_icon.py`（改配色只需调顶部常量后重跑）
